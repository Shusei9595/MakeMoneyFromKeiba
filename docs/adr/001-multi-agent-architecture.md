# ADR-001: マルチエージェントアーキテクチャの採用

## ステータス

承認済み

## 日付

2026-01-07

## コンテキスト

競馬予測は多面的な分析が必要であり、単一のモデルでは以下の課題がある：

1. **複雑性**: 競馬の結果は、馬の能力、騎手、コース適性、展開、オッズなど多くの要因に影響される
2. **専門性**: 各要因の分析には異なる専門知識とアプローチが必要
3. **保守性**: 単一の巨大モデルは理解・改善が困難
4. **拡張性**: 新しい分析観点の追加が難しい

## 検討した選択肢

### 選択肢1: 単一の大規模モデル

**説明**: 全ての特徴量を一つのモデル（例：XGBoost）に入力して予測

**メリット**:
- 実装がシンプル
- 特徴量間の相互作用を自動学習

**デメリット**:
- ブラックボックス化
- 特定分野の改善が困難
- 過学習リスクが高い

### 選択肢2: マルチエージェント（採用）

**説明**: 専門領域ごとに独立したエージェント（モデル）を作成し、予測を統合

**メリット**:
- 各エージェントの専門性向上
- 独立した改善・テストが可能
- 予測根拠の説明が容易
- 柔軟な重み調整

**デメリット**:
- 実装の複雑さ
- 統合ロジックの設計が必要
- 計算コストの増加

### 選択肢3: スタッキングアンサンブル

**説明**: 異なるアルゴリズムのモデルをスタッキング

**メリット**:
- 予測精度の向上
- 多様性の確保

**デメリット**:
- 専門性の観点が欠如
- 解釈性が低い

## 決定

**マルチエージェントアーキテクチャを採用する**

理由：
1. **説明可能性**: 各エージェントの予測根拠を提示でき、ユーザーの意思決定をサポート
2. **保守性**: 特定の分析領域（例：血統分析）のみを改善可能
3. **拡張性**: 新しいエージェント（例：AIオッズ分析）を追加しやすい
4. **ドメイン知識の活用**: 競馬の専門知識を各エージェントの設計に反映

## 結果

### ポジティブ

- 予測の説明可能性が向上し、ユーザー信頼を獲得
- チーム内で分担開発が可能
- A/Bテストによるエージェント単位の改善が可能
- 異常検出エージェントによるリスク管理

### ネガティブ

- 初期実装コストの増加
- エージェント間の重み調整にチューニングが必要
- テストケースが増加

### 実装詳細

9つの専門エージェントを以下の重み配分で統合：

| エージェント | 重み |
|-------------|------|
| 前走パフォーマンスAI | 25% |
| 距離・コース適性AI | 20% |
| 騎手・調教師AI | 15% |
| 血統AI | 10% |
| レース展開AI | 10% |
| 馬体・調教AI | 10% |
| オッズ分析AI | 5% |
| 統計パターンAI | 3% |
| 異常値検出AI | 2% |
