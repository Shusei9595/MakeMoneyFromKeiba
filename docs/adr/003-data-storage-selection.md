# ADR-003: データストレージの選択

## ステータス

承認済み

## 日付

2026-01-07

## コンテキスト

競馬AI予測システムは複数種類のデータを扱う：

1. **マスターデータ**: 馬、騎手、調教師の基本情報
2. **レースデータ**: レース情報と出走データ
3. **時系列データ**: 過去成績、オッズ推移
4. **学習データ**: 特徴量行列とラベル
5. **モデル**: 学習済みモデルファイル
6. **設定**: アプリケーション設定

データ規模の想定：
- レース数: 年間約3,500レース
- 馬数: 約25,000頭（現役）
- 過去データ: 10年分（約35,000レース）

## 検討した選択肢

### 選択肢1: 全てRDBMS

**説明**: PostgreSQLに全データを格納

**メリット**:
- 統一的なアクセス
- トランザクション保証
- SQLによる柔軟なクエリ

**デメリット**:
- 大規模行列データには非効率
- 設定変更にマイグレーションが必要

### 選択肢2: ハイブリッド構成（採用）

**説明**: データ種別に応じて最適なストレージを選択

**メリット**:
- 各用途に最適化
- スケーラビリティ
- 開発効率

**デメリット**:
- 複数技術の習得が必要
- データ同期の考慮

### 選択肢3: NoSQL (MongoDB)

**説明**: 全データをドキュメントDBに格納

**メリット**:
- スキーマ柔軟性
- 階層データに適合

**デメリット**:
- 分析クエリが非効率
- トランザクション制約

## 決定

**ハイブリッド構成を採用する**

| データ種別 | ストレージ | 理由 |
|-----------|-----------|------|
| マスターデータ | SQLite/PostgreSQL | リレーショナルな関係、参照整合性 |
| レースデータ | SQLite/PostgreSQL | 同上 |
| 学習用大規模データ | Parquet | 列指向で分析に最適、圧縮効率 |
| 設定ファイル | YAML | 人間が読みやすい、Git管理しやすい |
| モデルファイル | Pickle/Joblib | scikit-learn標準フォーマット |

### 開発環境 vs 本番環境

| 環境 | RDBMS | 理由 |
|------|-------|------|
| 開発・個人利用 | SQLite | セットアップ不要、単一ファイル |
| 本番・チーム利用 | PostgreSQL | 同時接続、バックアップ、スケーラビリティ |

## 結果

### ポジティブ

- 開発環境の構築が容易（SQLite）
- 大規模データの分析が高速（Parquet）
- 設定のバージョン管理が容易（YAML）
- 本番環境へのスムーズな移行パス

### ネガティブ

- データアクセス層の抽象化が必要
- 複数フォーマットの知識が必要

class RaceRepository(ABC):

    """開発環境用"""

    pass
