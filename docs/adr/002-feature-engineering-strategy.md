# ADR-002: 特徴量エンジニアリング戦略

## ステータス

承認済み

## 日付

2026-01-07

## コンテキスト

機械学習モデルの性能は特徴量の品質に大きく依存する。競馬データには以下の特性がある：

1. **時系列性**: 過去のレース履歴から特徴を抽出
2. **カテゴリ変数**: 競馬場、騎手、調教師など多数のカテゴリ
3. **欠損値**: データソースの制約による欠損
4. **スケール差**: 体重(kg)とオッズなど、異なるスケールの数値

## 検討した選択肢

### 選択肢1: 最小限の前処理

**説明**: 欠損値補完と標準化のみ実施

**メリット**:
- シンプルな実装
- 処理時間が短い

**デメリット**:
- モデル性能が限定的
- ドメイン知識が活かせない

### 選択肢2: ドメイン駆動特徴量設計（採用）

**説明**: 競馬ドメイン知識に基づく特徴量を明示的に設計

**メリット**:
- 高い説明可能性
- ドメインエキスパートとの協業が容易
- 過学習リスクの低減

**デメリット**:
- 設計に専門知識が必要
- 特徴量の網羅性に限界

### 選択肢3: 自動特徴量生成 (AutoFE)

**説明**: Feature Toolsなどによる自動生成

**メリット**:
- 網羅的な特徴量探索
- 人手の削減

**デメリット**:
- 計算コストが高い
- 生成される特徴量の解釈が困難
- 過学習のリスク

## 決定

**ドメイン駆動特徴量設計を採用する**

以下のカテゴリで特徴量を設計：

### 1. 前走系特徴量
- 直近N走の着順平均
- 直近N走の上がり3F平均
- 連対率・複勝率
- 休養明け日数

### 2. 適性系特徴量
- 同距離成績
- 同コース成績
- 同馬場状態成績
- 距離延長/短縮フラグ

### 3. 人的要因特徴量
- 騎手勝率
- 騎手×馬相性
- 調教師成績
- 騎手乗り替わりフラグ

### 4. 血統特徴量
- 父系統勝率
- 母父系統勝率
- 距離別血統適性
- 馬場別血統適性

### 5. 馬体・調教特徴量
- 馬体重増減
- 調教タイム
- 調教評価スコア

### 6. オッズ系特徴量
- 単勝オッズ
- オッズ変動率
- 人気順

## 結果

### ポジティブ

- 各エージェントに最適化された特徴量セットを提供
- 特徴量の意味が明確で、デバッグが容易
- 新しい特徴量の仮説検証がしやすい

### ネガティブ

- 初期設計に時間を要する
- 特徴量追加時にコード変更が必要
- ドメイン知識のない特徴量は発見されない

### 実装方針

```python
# 特徴量カテゴリごとにクラスを分離
class RecentPerformanceFeatures:
    """前走系特徴量を生成"""
    
class CourseAptitudeFeatures:
    """適性系特徴量を生成"""
    
class JockeyTrainerFeatures:
    """人的要因特徴量を生成"""

# パイプラインで統合
class FeatureEngineeringPipeline:
    def __init__(self):
        self.generators = [
            RecentPerformanceFeatures(),
            CourseAptitudeFeatures(),
            JockeyTrainerFeatures(),
            # ...
        ]
```
